- Fixed the v1/v2 session migration handing out a short entry id it had already used. A repeated id joins two points of the parent chain, so the leaf-to-root walk in `buildSessionContext` never reached the root: it grew its path array until V8 raised `RangeError: Invalid array length` and the session failed to load. The migration now records every id it assigns, so its collision avoidance can see one, and that walk stops at the first id it has already visited, the way `branchEntries` in `context-tree.ts` already does, so a session file that carries a repeated id loads every entry the chain can reach instead of failing.
