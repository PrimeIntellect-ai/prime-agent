- Replaced the twelve per-kind continual-harness CRUD methods (`create_memory`, `update_skill`, `delete_prompt_note`, ...) with one generic trio: `rlm.harness.create(title, content, kind=...)`, `rlm.harness.update(id, title, content, kind=...)`, and `rlm.harness.delete(id, kind=...)`. `kind` defaults to `memory`, only skill entries accept `reference`/`arguments`, and the old names now raise an error naming their replacement. Renamed the entry grouping field from `path` to `topic` everywhere it is visible to the model; harness state files written before the rename still load, and the next save rewrites them with `topic`.
