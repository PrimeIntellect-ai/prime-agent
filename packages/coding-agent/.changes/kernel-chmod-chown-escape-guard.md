- Added a recursive chmod/chown guard to the kernel bash tool: `chmod`/`chown` invocations carrying a recursive flag (`-R`, `--recursive`, bundled short options, flags in any position) are refused before execution when an operand resolves outside the current workspace (HOME itself, `/`, parent directories, other trees, symlink escapes), names a protected dot path (`.git`, `.env`-class dotfiles and dot-directories), or cannot be checked statically (globs, substitutions, unknown variables); quoted command words and flags scan like their unquoted forms, and `eval`, `sh -c`, `xargs`, and unreplayable `cd` wrappers are refused outright. Hardened against red-team bypasses of the first cut: command names built from variables or command substitutions (`$cmd -R ...`, `$(printf chmod) -R ...`, including behind xargs/sudo/env and similar executors), ANSI-C quoted command names, flags, and operands (`$'chmod' $'-R' ...`, plus `$"..."` locale quoting), GNU's abbreviated `--recursive` prefixes (`--rec` through `--recursiv`), nested or mixed quoted wrappers (`eval`/`sh -c` one inside another, quoted payloads rescanned one layer at a time), process substitutions feeding a shell wrapper (`bash <(...)`), and BASH_ENV (an inherited BASH_ENV/ENV is stripped from the kernel child environment, and arming BASH_ENV from the command is refused); relative `cd` relocations are refused while CDPATH is armed (inherited or assigned in the command) because bash searches CDPATH directories first, and the xargs walk no longer misreads an operand named `xargs` or a later `xargs` pipeline as wrapping a first-word recursive chmod. A second red-team round is also closed: quote- or ANSI-C-encoded wrapper names (`e"val"`, `b"ash" -c`) trigger the wrapper payload scans through the parsed words instead of raw-text regexes; glob/brace-expandable command words (`chmo?`, `{ch,}mod`) are refused; here-document bodies are masked through their terminator so an unmatched quote in the body cannot hide a later real command (here-strings stay visible to the wrapper-fed checks); shell function definitions and alias bodies that can carry a recursive chmod (`f() { chmod "$@"; }; f -R 755 /`, `alias x='chmod -R 755 /'`) are refused; wrapper options before a process substitution (`bash -- <(...)`) and wrapper stdin fed by a pipe or here-string (`printf ... | bash`, `bash <<< ...`) are refused; and the CDPATH exemption now matches bash exactly (only `.`, `..`, `./`, `../` prefixes skip CDPATH; dot-named targets like `.config` still consult it). A third red-team round is also closed: here-document bodies that execute as shell code — a wrapper fed by the heredoc (`bash <<EOF ... EOF`, scanned with the full guard so in-workspace recursion stays allowed) or a heredoc flowing out of a command substitution (`eval "$(cat <<EOF ...)"`) — are scanned instead of staying masked; wrapper option arguments (`bash -o vi <(...)`, `bash --rcfile <(...)`) no longer hide a process substitution from the wrapper check (any input-feeding marker in the wrapper's command region refuses it); function bodies in subshell form (`f() (chmod "$@"); f -R ...`) are refused like brace bodies; and a trailing heredoc operator is a shell syntax error instead of a guard crash. A fourth red-team round is also closed: an ANSI-C escape above Unicode's maximum code point is preserved instead of crashing the guard; a bare shell wrapper whose script input (argument, `source` target, or stdin redirect) resolves outside the kernel workspace — or cannot be resolved — is refused, while in-workspace scripts and `-c` payloads stay fine; trap bodies (`trap 'chmod -R ...' EXIT/DEBUG/ERR`) are scanned like wrapper payloads and refused when they hide shell code; the command-executing wrapper set for dynamic command names grows to nice/timeout/setsid/stdbuf/ionice/parallel/time/strace/valgrind; a quoted `eval`/`sh -c` payload whose command position is a variable or substitution (`p='chmod -R ...'; bash -c "$p"`, unquoted `$(...)` payloads) is refused outright because the whole payload could be the unguarded command; and substitution spans are recorded inside double quotes too, so the heredoc-body scan covers `eval "$(cat <<EOF ...)"` deterministically. A fifth red-team round is also closed: containment is answered from a scan-time flag so the guard stays linear on commands with thousands of separators (quadratic before); wrapper script inputs replay cd relocations, resolve behind every command-executing wrapper and inside quoted payloads, skip option words and the values of `-o`/`-O`/`--rcfile` (unknown long options fail closed), cover the `<>` read-write redirect, resolve slash-free `source` operands through PATH like bash, and allow in-workspace dot-path scripts (the chmod dotfile policy applies to chmod targets, not script inputs). A sixth red-team round is also closed: `env -C`/`--chdir` and `find -execdir` relocations refuse with the existing relocation error, GNU `env -S`/`--split-string` payloads are scanned like wrapper payloads, a relocating command prefix makes wrapper scripts unresolvable, bundled option values (`-ovi`) no longer hide the script operand, and slash-free `source` PATH hits are realpath'd with PATH assignments in the command refused outright. Explicit bypasses: `bash(command, allow_destructive_chmod=True)` or `PI_BASH_ALLOW_DESTRUCTIVE_CHMOD=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
- A seventh red-team round is also closed: the wrapper chain that runs the invocation is walked instead of only its head, so `nice env -C / chmod -R 755 .`, `timeout 5 env -C / chmod -R 755 .`, and `nice xargs chmod -R 755` are refused like their head-only forms; GNU `env -C`/`--chdir` is read the way `env` reads it (`-C/`, `-iC /`, `--chdir=/`); GNU `env -S`/`--split-string` is read in every spelling (attached `-S...`, bundled `-iS ...`, `--split-string=...`), every `-S` string of every `env` word is scanned (a clean string no longer stops the walk, and an `env -S` payload inside `eval`/`sh -c`/`trap` is scanned too), while a string carrying expansion is refused with its own message; `hash -p pathname name` registrations are tracked, so the registered name scans as the command it runs and an unreadable registration is refused because the command it hides cannot be resolved; a login or interactive shell (`-l`, `--login`, `-i`, `--interactive`, and the `-lc`/`-ilc` clusters) is refused because profile and rc files run before the payload the guard was given, with `--rcfile`/`--init-file` kept as bash's rc-file option; the relocating-prefix check applies only to a word that actually introduces a wrapper, so `echo bash`, `ls .`, and `echo source` run again; and an append assignment (`PATH+=...`) is read as an assignment, so the slash-free `source` PATH gate covers it.
- Frozen scope after the seventh review round, stated rather than open-ended because the guard is a static approximator over command text: it is a foot-gun guard for the model's own commands, not a sandbox — a recursive `chmod`/`chown` hidden in a binary, in a file the command merely names (an in-workspace script argument or a `source`d file), or behind a launcher the model does not name can still run; text a shell reads from a file is never read by the guard, which is why a login or interactive shell is refused outright rather than scanned (`--norc`/`--noprofile` are not an exemption, because bash reads a system-wide startup file too on some platforms; `--rcfile` without `-i` is not read by bash and keeps its previous treatment); the wrapper chain is the ordered run of names in `_UNRESOLVABLE_COMMAND_EXECUTORS`, in any of their option spellings, and a launcher outside that list (busybox, doas, chroot) does not continue it; command-name indirection is resolved through assignment prefixes, `hash -p` registrations, quoted and ANSI-C names, and the executor chain, and refused when a name's source cannot be read at all; and `env` option spellings are read from the words, with every `--split-string` value scanned, so a platform that honors a different precedence refuses more, never less.
- Incompleteness remains inside the approximation families this guard is built from, and is stated rather than claimed away: the executor list above, command-word spellings the scanner folds (quotes, escapes, ANSI-C, common prefixes), operand resolution against the kernel cwd with replayed `cd`/`env -C` relocations, and the wrapper payload kinds (`eval`, `sh -c`, `alias`, `trap`, `env -S`) unquoted one level at a time. Every verified case in these families is fixed and carries a regression test; a spelling outside the model is refused when the guard cannot read it and otherwise stays inside these families.
- Residual cost, measured on this machine: ~0.08 ms for a typical short command (`git status --short && ls -la sub`; 0.07 ms before this round), ~0.17 ms for one that carries the chmod walk (`cd sub && nice env -C / chmod -R 755 .`), and ~2.2 µs per character of plain text, which stays linear (32 KB 81 ms, 64 KB 159 ms, exactly double). Every check is an explicit linear pass; no path polls, sleeps, or spawns.
- An eighth red-team round is also closed, each case verified as an outside-workspace recursive chmod through a real kernel spawn before the fix: a PATH assignment with an empty, `.`/`..`, or relative entry (or an absolute entry that resolves inside the workspace) can make a bare `chmod`/`chown` word run a workspace file, so that invocation is refused while a slash-qualified word and a `hash -p` registration stay checked as before; line continuations are removed inside a word as well (`ch\<newline>mod -R 755 ~`, `ch"mo\<newline>d" -R 755 ~`), because the scan folds the removed pair into the word instead of leaving a word break; exported shell functions (`BASH_FUNC_name%%`) are stripped from the kernel child environment, so an imported body the guard never reads can no longer run a recursive chmod under a name the guard only sees as a word; `env` value options are read the way `env` reads them inside a short cluster (`-iC<dir>`, `-iS<argv>`, `-iC dir`) and through the GNU long-option prefixes of `--chdir`/`--split-string`; the wrapper chain continues through an assignment prefix, a grouping token, or a group keyword (`FOO=1 env -C / chmod -R 755 .`, `{ env -C / chmod -R 755 .; }`); the login/interactive refusal reaches the same forms (`{ bash -l -c ':'; }`, `if true; then bash -l -c ':'; fi`); a `hash -p` pathname attached to its flag (`hash -p/bin/chmod safe`) is read, and a globbed or expansion-built registration (`hash -p /bin/chmo? safe`) is refused with the unreadable-registration message; and the append-assignment spellings arm their gates (`BASH_ENV+=` arms the startup file, `CDPATH+=` arms the cd search path).
- Frozen scope after the eighth review round, restated because this round changed three of the clause details it inherits from the round-7 list above: the guard is a foot-gun guard for the model's own commands, not a sandbox; text a shell reads from a file is never read, which is why a login or interactive shell is refused outright rather than scanned (and why an in-workspace script argument stays allowed); the wrapper chain is the ordered run of names in `_UNRESOLVABLE_COMMAND_EXECUTORS` after assignments, grouping tokens, and group keywords, and a launcher outside that list (busybox, doas, chroot) does not continue it; command-name indirection is resolved through assignment prefixes, `hash -p` registrations (detached, attached, or bundled `-p`), quoted and ANSI-C names, and that chain, while a registration built from expansion or a glob is refused; a bare command word is refused when the PATH it resolves through has an entry the guard cannot trust (empty, relative, or resolving inside the workspace), rather than resolving the word itself; and `env` option spellings are read from the words, with every `--split-string` value scanned, so a platform that accepts a different spelling refuses more, never less.

- The continuation fold from this round was corrected before the freeze: the two-character placeholder it first used fused with a preceding `$` into ANSI-C quoting, so `$<continuation>cmd -R 755 /` scanned as the literal word `cmd` (verified: the outside chmod ran through a kernel spawn). - Command-substitution nesting deeper than a fixed bound now refuses with the guard's own error instead of crashing `bash()` with `RecursionError`: the word scanner recurses once per nesting level, so roughly 500 quoted or 900 unquoted `$(` levels exhausted Python's stack before the fix (real bash parses 1100+ levels and runs them), and hostile input must refuse, not crash. Any nesting at or under 100 levels scans exactly as before, well above any real command.
- The substitution matcher tracks quote and escape state: a `)` inside single quotes, double quotes, ANSI-C quoting, or backticks (or behind a backslash) is data, so `$(echo ')'; chmod -R 755 /)` closes at the real `)` and its interior is scanned. Fail-pre-fix, verified through kernel spawns: the blind paren count stopped at the quoted `)`, folded the rest of the substitution into the enclosing word as data, and the outside recursive chmod ran (`echo "$(echo ')'; chmod -R 755 <outside>)"` plus the unquoted, double-quoted, ANSI-C, escaped, and backtick forms; real bash runs each shape).
