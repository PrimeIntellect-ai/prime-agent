- Added a recursive-force rm guard to the kernel bash tool: `rm` invocations combining recursive and force flags (`-rf`, `-fr`, `-Rf`, `--recursive --force`) are refused before execution when an operand resolves outside the current workspace (HOME itself, `/`, parent directories, other trees, symlink escapes), names a protected dot path (`..`, `.git`, `.env`-class dotfiles), or cannot be checked statically (globs, unknown variables, substitutions, stdin name lists, `find -exec` placeholders, no explicit operand). Explicit bypasses: `bash(command, allow_destructive_rm=True)` or `PI_BASH_ALLOW_DESTRUCTIVE_RM=1`, where the env bypass is frozen at kernel start so mid-session `os.environ` writes cannot neuter the guard (they are ignored and warned about loudly).
- Hardened the recursive-force rm guard against the wrapped and dynamic bypass classes found by red-team review: quoted `sh -c`/`bash -c`/`eval` payloads are scanned as live command strings; substitution matching is quote-aware, so a `)` inside a quoted string cannot close a `$(...)` scan early and hide a live `rm`; command words or flags hidden behind variable or brace expansion (`R=rm; $R -rf ...`, `flags=-rf; rm $flags ...`) are refused as unresolvable; `cd`/`pushd` relocations are tracked with subshell scoping, so relative operands resolve against the directory the shell will actually run in (unresolvable relocations fail closed); the guard scans the `PRIME_AGENT_BASH_COMMAND_PREFIX` spawn preamble exactly as the shell executes it (that env value is model-writable mid-session); and operand identity is verified at check time, refusing symlinked operands and paths that do not exist yet because they can be swapped or created as symlinks before the run.
- Hardened the same guard against the second red-team round: GNU long-option abbreviations (`rm --recurs --forc`) are treated as their full options; `trap` action strings are scanned as live command payloads; expansion command words in assignment-prefix, env, keyword, and grouping positions (`FOO=1 $R -rf ...`) are refused when rm-shaped flags sit adjacent; and here-document bodies that feed non-interpreter commands are data, not live commands (interpreter- and pipeline-fed heredoc bodies stay scanned).
- Third hardening round: the wrapper scan matches parsed word values on the pre-scanned words (escaped `t\\rap`, `ev\\al`, and `bash -\\c` forms can no longer slip past the raw-substring gate), `trap -- 'action'` end-of-options forms are scanned, and heredoc bodies stay live whenever any interpreter or unresolved-expansion word appears anywhere in the command (closing `{ cat <<EOF ... } | sh` and `cat <<EOF > s.sh; sh s.sh` execution paths).
- Fourth hardening round: backslash-newline continuations are now removed the way the shell removes them (intra-token splits like `r\\\n`m no longer hide `rm`), commands that reassign `HOME`/`PWD` lose the guard's trust in `$HOME`/`~`/`$PWD` operand expansion, `_child_env()` no longer forwards `BASH_ENV`/`ENV` so a mid-session env write cannot point the shell at an unscanned startup file, and heredoc handling now scans the outer command with bodies blanked plus each runner-reachable body as its own command text — so an unbalanced quote in a data body can no longer hide a later `sh`-fed body, and `source`/`.`/`./script` runners keep bodies live.
- Fifth hardening round: interpreter `-c` payloads are located through the full option list (`bash -e -c`, bundled `bash -uc`), escaped characters no longer open fake quoted spans in the continuation joiner, `unset HOME`/`HOME+=` reassignments make `$HOME`/`~`/`$PWD` operands and `cd ~` relocations untrackable, heredoc bodies inherit the outer command's cd/HOME context by resolving against every script runner's tracked directory, and `exec`/`sudo`-prefixed script paths (`exec ./s.sh`) keep heredoc bodies live while plain cd targets do not.
- Sixth hardening round: the interpreter `-c` locator walks the whole option list (bundled `-ce`, behind argument-taking options like `-o pipefail`), wrapper payloads scan the scanner's folded word values so adjacent quoted fragments (`'r''m -rf x'`) stay one word, `CDPATH` (inherited or reassigned in-command) makes relative cd targets untrackable, `PWD` reassignments make `cd "$PWD"` untrackable, `cd -P`/`-L` options are no longer treated as directory operands, and the directory tracker models `&&`/`||` control flow with candidate directories — `cd A && true || cd B && rm` resolves against every reachable directory instead of assuming the last cd ran.
- Seventh hardening round: pipelines feeding a bare stdin shell (`printf 'rm -rf x' | sh`) have their producer text scanned as command input (both raw and escape-interpreted, against the interpreter's tracked directories), and the directory tracker no longer assumes an `&&`-chained cd ran — failed-chain exit directories stay in play at statement boundaries, so `cd /outside; false && cd /workspace; rm -rf x` resolves against every reachable directory; provably succeeding relocations (existing directories) keep `cd sub && rm -rf nested` and `cd sub; rm -rf nested` precise.
- Eighth hardening round: here-document operators attached to the command word (`sh<<EOF`) are recognized (arithmetic `<<` in `$((...))` reports no span and stays harmless), stdin-shell feed scanning covers `|&` pipelines, `{...}`/`(...)` grouped producers (the window crosses `;` and newlines inside groups), interpreters named through unresolved expansion (`| $SHELL_BIN`), and `-s` shells that keep reading stdin with positional arguments — while statements before an ungrouped pipe stay outside the feed window.
- Ninth hardening round: wrapper payloads (`sh -c "$SCRIPT"`) whose command-position words expand at run time are refused as unresolvable instead of being scanned literally, and arithmetic substitutions (`$((x<<y))`) are skipped by the here-document span parser so their shift operator can never parse as a heredoc and blank live commands.
- Tenth hardening round: aliases defined in the command (`alias wipe='rm -rf x'; eval wipe`) are tracked and expanded in eval/trap payloads before scanning; live here-document bodies carrying command substitution are refused because the consuming shell executes the unknowable output; the `$((...))` arithmetic skip is quote- and escape-aware so a quoted paren cannot keep it open past real heredocs; `_expansion_is_resolvable` matches full variable names (`$HOMEFOO` is no longer treated as `$HOME`), and any expansion word in a wrapper payload's command position is refused — resolvable or not.
- Eleventh hardening round (regression close): wrapper payload command-position words are refused for every run-time expansion form — `$` variables, backticks, and brace expansion — restoring the round-9 coverage the round-10 `$`-only check had narrowed.
- Twelfth hardening round (rebase regression close): the guard's body and stdin-feed passes now split each scan text with the runner-aware here-document scanner (recursively) before masking redirections, so the blanket heredoc masking shared with the git guard can no longer blank interpreter-fed bodies nested inside a runner-reachable body or inside text piped to a stdin shell (`printf 'sh <<EOF\nrm -rf x\nEOF' | sh`, literal or escaped newlines); data bodies keep their consumer-aware silencing, `is_recursive_force_rm_command` documents its consumer-agnostic heredoc masking, and guard decisions keep the runner-aware path.
- Thirteenth hardening round: `_child_env()` strips `PI_BASH_ALLOW_DESTRUCTIVE_RM` unless the launch-time snapshot authorizes it, mirroring the git-bypass strip, so a mid-session `os.environ` write cannot leak into child kernels and arm their frozen launch-time snapshot (falsy launch values such as `0` stay stripped too).
- Fourteenth hardening round: the body-pass worklist now carries HOME/PWD/CDPATH reassignment context into every nested here-document body it queues (a reassignment made in a runner-fed outer body keeps tracking the bodies it wraps), restoring the pre-split whole-body semantics at any depth; the stdin-feed pass keeps the outer-command flags exactly as before.
- Fifteenth hardening round: blanked data here-document bodies keep command-substitution spans live in the outer scan (the shell expands `$(...)` and backticks in an unquoted body even when the consumer only prints it, mirroring the git guard's heredoc masking), so a `cat <<EOF` data body can no longer smuggle an executing substitution past the rm guard — runner-reachable bodies keep their separate scan and their live-substitution refusal.
- Sixteenth hardening round: a here-string feeding a bare stdin shell (`sh <<< 'rm -rf x'`) is scanned as the command text that shell runs, and an operand the shell builds from expansion is refused; a process substitution consumed as a script argument (`bash <(printf 'rm -rf x')`) is refused because the produced script text cannot be checked, while data arguments (`cat <( ... )`) stay untouched. Exported shell functions (`BASH_FUNC_name%%` entries) are scanned as wrapper payloads and stripped from child environments, so a model-written function cannot shadow `rm` in a spawned shell, and a command-level `BASH_ENV` assignment is refused because it points a child shell's startup at a file the guard never sees. Aliases that the shell can still apply — a definition on an earlier line of a payload, eval/trap action, stdin-fed text, or runner-fed body — substitute the aliased command word before scanning (`alias del='rm'` then `del -rf x` is checked as `rm -rf x`), while a same-line definition, which the shell parses before the alias exists, is left untouched. The unresolvable-operand refusal is narrowed to expansions that can still produce recursive-force rm: `rm "$file"`, `rm -f "$file"`, and `rm -- "$file"` run again, while word-splitting expansions (`rm $flags`) and single-word expansions sharing the invocation with another operand (`rm "$flags" /outside`) stay refused. Inline shell-fed text inside runner-fed bodies (nested here-strings, pipelines, and process substitutions) is scanned too.
- Seventeenth hardening round: a command word the command itself builds is resolved before scanning — a literal assignment substitutes into a later `$NAME` command word (`X='rm -rf /outside'; $X`), and a value the command builds from expansion or substitution (`X=$(cat cmd); $X`) is refused because its text cannot be read. Payloads now run the same unresolvable-expansion refusal as the outer scan, so `sh -c 'flags=-rf; rm $flags /outside'` (and its `eval`/`trap` forms) is refused. `popd` and stack rotations (`pushd +1`) no longer leave the tracked directory stale, so a relative rm after them fails closed, and the unused `_paren_positions` helper is gone.
- Eighteenth hardening round: glob characters in command or flag position are refused as unresolvable (`?m -rf /outside` runs `rm -rf /outside` when a matching file exists, `-?f` becomes `-rf`), while `*`/`?`-only operands of a non-recursive rm and the `[` test builtin stay literal. A pipeline producer's `printf` output is reconstructed from its format string (`printf '%s%s %s %s\n' r m -rf /outside | sh` writes and runs `rm -rf /outside`) and the first word of the producer window is no longer dropped from the synthetic text. Alias expansion that hits the pass limit now fails closed instead of scanning a partial chain, and the alias detection reads scanned words rather than a raw `alias` substring, so a name folded across quotes (`al''ias`) is still found. Quoted `"$@"`/`"${name[@]}"`/`"$*"` are tracked as word-splitting, `NAME+=value` assignments are resolved like `NAME=value`, and a `-c` payload that reads its stdin (`sh -c 'exec sh' <<< 'rm -rf x'`) consumes the here-string operand as its commands.
- Nineteenth hardening round (frozen-scope round): three argv-relocation and quoting bypasses that break the guard's headline claim are closed. GNU `env -C dir`/`--chdir=dir`/`-iC dir` relocates the command it runs, so it is now tracked like `cd` (the relocation follows the same candidate-directory model, and an unresolvable target fails closed) while `env -C <workspace>/sub rm -rf nested` keeps working. GNU `env -S '<argv text>'`/`--split-string=<argv text>` splits its string into the argv it runs, so the split words are scanned as command text and a string carrying expansion is refused (`env -S 'VAR=1 echo hi'` still runs). Bash ANSI-C quoting now decodes before classification (`$'rm' $'-rf' /outside` and `$'\x72m' $'-rf' /outside` are refused as `rm -rf /outside`), with unknown escapes and out-of-range code points kept as written; `$"..."` translation quoting folds like a double-quoted string.
- Twentieth hardening round (final authorized round): five approximation edges inside the guard's headline promise are closed, each verified as an outside-workspace deletion before the fix. Shell option arguments are consumed the way the shell consumes them (`-o`/`-O`/`--option` take the next word), so `bash -O extglob <<< 'rm -rf x'` and a pipeline into `bash -O extglob` are scanned instead of treating `extglob` as a script argument. Quoted word-splitting references now cover the braced spellings (`"${@}"`, `"${*}"`, `"${@:1:2}"`) alongside `"$@"`/`"$*"`/`"${name[@]}"`, and a literal `[@]` stays data. The `printf` producer reconstruction finds the command word through assignment, grouping, and exec-style prefixes (`X=1 printf ...`, `command printf ...`, `! printf ...`) and scans every assembled line when arguments outlast the format (which reuses it). A `NAME+=value` append with no value the command itself set is untrackable, so a later `$NAME` is refused rather than resolved to the appended piece alone.
- Final micro-round: the fed-text scan now runs the startup-file check too, so `env -S 'BASH_ENV=startup.sh bash -c true'` is refused (the argv `env` builds is read by a fresh bash, which sources that file before running anything; the direct `BASH_ENV=... bash -c ...` form was already refused), and `_command_reassigns_env` counts an assignment only where the shell reads one — an assignment prefix or an argument to `export`/`declare`/`local`/`readonly`/`unset` — so an ordinary argument that looks like one (`echo PWD=/tmp; rm -rf "$PWD/sub"`) no longer makes `$PWD`/`$HOME` untrackable, while the real reassignment forms stay refused.
- Regression close after the final micro-round: `_command_reassigns_env` keeps the assignment slot open across keywords and grouping tokens (`{ PWD=/x; }`, `if true; then PWD=/x; fi`, `for i in 1; do PWD=/x; done`), which the round-21 slot rule had closed, so those live reassignments again make `$PWD`/`$HOME` operands untrackable while `echo PWD=/tmp` stays an ordinary argument.
- Post-freeze authorized close on the two held bot findings, each a verified outside-workspace deletion against real bash with a pre-fix guard allow: the assignment resolver now applies the shell's position rule (the same one `_command_reassigns_env` models for HOME/PWD), so an ordinary argument that merely looks like an assignment (`echo a X=b`, `echo export X=hi`) is data for its command and cannot overwrite a recorded assignment and hide the text a later `$NAME` runs; `unset` removes only plain names in its own argument list, and `unset -f` names functions, so neither spelling hides a variable (`echo unset X` and `unset -f X` keep the refusal); and the `$NAME` reference gate now covers every position the shell runs a word from — an assignment prefix (`FOO=1 $X`), the word after an executing keyword or grouping token (`{ $X; }`, `if $X; then ...; fi`), and the word after an exec-style prefix (`env $X`, `command $X`). Exec-style options and their arguments keep the stated option-argument residual, and list positions (`for i in $X`) stay unresolvable. A regression close on this close: a reserved word in an argument position (`echo if X=b`) is data and cannot reopen the assignment slot, a builtin's argument list runs to the command boundary the shell's parser gives it (`export A X=1` assigns X; `declare +x X=1` too; a reserved word inside it is just a name), and redirections are masked before the resolver's word scan, so a redirection target (`cat > if X=b`) and the words after it belong to the running command instead of opening a fresh command position that records a decoy — each closed shape is again a verified outside-workspace deletion against real bash with a pre-fix guard allow.
- Frozen scope after the round-18 review round, stated rather than open-ended because the guard is a static approximator over command text: (a) text a shell reads from a file argument is never read by the guard, so `sh script.sh` and `sh /dev/stdin` are covered only when the command writes that text itself (a here-document in the same command); (b) a pipeline producer whose output is not literal text keeps the synthetic-text approximation — the guard scans the producer's word values and reconstructs `printf` output from its format string, but it does not read a file or the network, so `cat script.sh | sh` and `curl ... | sh` are unchanged, because refusing them outright would refuse the product's own installer path (`curl -LsSf https://astral.sh/uv/install.sh | sh`, `packages/coding-agent/src/core/kernel/bootstrap.ts`) and the separate remote-download guard (#2415) covers that case on its own terms; (c) alias definitions count as effective without requiring `shopt -s expand_aliases`, deliberately fail-closed, so a definition the shell never applies is refused rather than assumed inert.
- Incompleteness remains inside the approximation families this guard is built from, and is stated rather than claimed away: option-argument consumption (`-o`/`-O`/`--option`), parameter-expansion spellings (`$@`, `"${@}"`, array forms, and array slices such as `"${arr[@]:0}"`), producer-prefix forms (`X=1 printf`, `command printf`, `{ printf ...; }`, and producer escape decoding such as `printf`'s octal, hex, and `\c` escapes), and assignment accumulation (`NAME+=`, literal versus environment values). Each verified case in these families is fixed and carries a regression test, and every such check is now run to the best of the scan's model, but a static approximator over shell text cannot be complete: a spelling outside the model is refused when the guard cannot read it and otherwise remains inside the families above. Two verified cases sit in these families as documented residual at the freeze point rather than being patched: producer escape decoding (`printf 'r\155 -rf /outside\\n' | sh`, which emits `rm -rf /outside`) and array-slice parameter spellings (`arr=(-rf /outside); rm "${arr[@]:0}"`).
- Residual cost, measured on this machine: ~0.07 ms for a typical short command (`git status --short && ls -la sub`), ~0.15 ms for a pipeline/here-document command, and ~0.85 µs per character of plain text, which is linear (1 KB 0.9 ms, 4 KB 3.4 ms, 16 KB 13.4 ms, 64 KB 56 ms). Quoted-fragment-heavy input runs ~2.1 µs per character (16 KB in 2000 quoted fragments measured 34 ms), and alias-definition-heavy input ~1.6 µs per character (8 KB in 800 definitions measured 13 ms). Here-string operands were quadratic (each operand re-scanned the word list: 8 KB in 800 operands measured 290 ms) and now scan the precomputed interpreter candidates instead, measuring 12.9 ms for the same input. Every check is a single pass over the text for the shapes agents actually write, with one known quadratic class: `_unresolvable_expansion_rm_reasons` materializes the follower run of every word, so a command whose words sit in one long run costs O(words squared) — measured on this machine at 1 KB/498 words = 5.0 ms, 4 KB/1998 words = 48 ms, and 16 KB/7998 words = 649 ms for `echo x x x ...`. Making that linear needs per-run suffix accumulators in all three of the helper's branches, and the rm-word branch names the first offending token in its refusal, so a rewrite risks message drift; it is recorded here as a known cost class rather than patched inside the freeze. No path polls, sleeps, or spawns.
