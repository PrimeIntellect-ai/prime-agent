feat(bots): a bot spawned with `rlm.spawn(..., target="sandbox", bots=True)` can spawn its own bots. The Mac provisions a platform header rule that injects the owner's sandbox API key on api.primeintellect.ai into that bot's sandbox (the key value never enters the VM), so the bot creates, pauses, and deletes its children directly through the sandbox API and keeps working while the Mac sleeps. Bots nest two levels deep (owner -> bot -> bot), children count toward the owner's `bots.maxBots` (default 10), and deleting a bot deletes its descendants first. `rlm.spawn(target="sandbox")` inside a bot that was not spawned with `bots=True` now fails fast with "this bot may not spawn bots" instead of a platform 401, and a failed spawn's cleanup error no longer masquerades as the headline. `prime-agent bots allow-spawns <bot>` gives an existing bot the same rule, guest settings, and nested context without a respawn. The /bots page shows the tree (children indented, a "spawns bots" mark). Security note: with `bots=True`, any code inside that bot can call the whole Prime sandbox API as the owner - create, delete, or exec into any sandbox of the account - so give such bots a dedicated, sandbox-scoped API key you can disable alone.
