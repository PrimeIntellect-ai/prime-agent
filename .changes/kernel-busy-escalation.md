- A `python_repl` call that arrives while an aborted cell still holds the kernel no longer returns "The Python kernel is still running the previously interrupted cell" forever: when the interrupted cell was one the host already gave up on, the kernel now restarts and the cell runs on the fresh kernel, with the usual `<ipython_kernel_reset>` notice (variables, imports, and async tasks from before the restart are gone). A cell still running under its own caller keeps the old wait-and-retry message.
