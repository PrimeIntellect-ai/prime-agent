- Native `rlm_heartbeat` jobs now survive a bot pause. With `bots.relay.url` set, a bot's guest daemon mirrors every heartbeat's next run time to the relay (a daemon-wide full-set `PUT /api/bots/{botId}/wakeups`, using the same per-bot token on the relay host as the self-pause). The relay resumes a paused sandbox when a heartbeat is due; the guest's local scheduler remains the only firing path, so a wake never duplicates a prompt. The guest re-mirrors on boot, on every heartbeat change and fire, and just before it pauses. Deleting a bot sends `DELETE /api/bots/{botId}` so its schedules can never fire. The scheduler also rechecks the wall clock every 30 seconds, and the guest self-pause holds off while a heartbeat is due, so a VM resume fires an overdue heartbeat and never re-pauses before its turn starts.
