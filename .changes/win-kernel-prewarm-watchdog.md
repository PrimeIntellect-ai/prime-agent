- The Windows install no longer hangs forever at the kernel pre-warm: the product's bootstrap spawns its uv children with drained pipes (forwarded through the pre-warm's own progress lines, never the shared console the CREATE_NO_WINDOW child does not own), runs them with `--no-progress` and a null stdin, and bounds every child wait - an unresponsive `uv python install` is tree-killed at the bound (`PRIME_AGENT_BOOTSTRAP_CHILD_TIMEOUT_MS`, default 10 minutes) instead of holding the install indefinitely. Both installers belt the pre-warm with their own watchdogs: install.ps1 watches the payload exe as a bounded child and tree-kills it with the absolute-System32 `taskkill /T /F` on expiry; install-rust.sh runs the launcher under the same portable runner-and-done-marker watchdog the `--version` probe uses. On expiry both degrade to the honest note the offline path already prints - the first session bootstraps the kernel itself and needs the network once - and the install still succeeds.
