- A machine run follows a defined state model. A state with `join = [...]` waits for every state it names. A run and each state can have a time budget. A status change that the model does not allow is an error. The run then stays as it was.
- Only the session that owns a run can advance it. An owner can abandon a run. Another session can then take it over. A state finishes only when all its subagents are done and its result is saved.
- A state gets its inputs as one typed record. Each field names a parent state and one output, as `<state>.<port>`. The field takes the latest value of that output. An ambiguous reference, such as `a.b.c`, fails before the run starts.
- A machine directory keeps its own files: prompts, scripts, rubrics, and assets. A state reads a file under `assets/` as a text input, such as `style = "assets/style.md"`. A path that leaves the directory, through `..` or a symlink, is an error. The error names the path and the directory. A symlink error also names its target.
