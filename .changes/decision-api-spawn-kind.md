- `rlm.spawn(kind="decision")` spawns a Decision API child served by the `decisionModel` setting: a JSON decision request (`seq`, `state`, `questions`, at most 4 `images`) comes back to the spawning agent's inbox as a tagged `decision_api.decision` agent message carrying the request's `seq` (a request without one answers with `seq: null`), the spawn task itself readies the child ("Decision child ready.", no decision), and a message that is not a valid request answers with an error reply. The parent reads replies with `rlm.inbox.read(sender=<child name>)`: a reply wakes an idle parent with a short inbox notice, replies that arrive while it is busy coalesce into one extra turn, and a running cell can read waiting replies without ending its turn.

- Decision API children stay out of the user's way: the agents view renders no row for them and never counts them in its subagent readouts, while their spend keeps rolling up into the parent (`rlm.list_subagents` and the spawn ledger still list them).
