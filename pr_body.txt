## Summary

Salvage of the dead term-enhanced-keys lane plus the key/paste parity finish. One surface: terminal input for the TUI.

- **Bracketed paste enable (?2004)**: every TUI surface start writes ?2004h, teardown writes ?2004l (TS parity). Without this, tmux wrapped-paste markers never reach the reader and a 20-line paste lands as raw characters per line (the Kevin dogfood bug) — the collapse-marker editor path (handlePaste port, already on main) was unreachable.
- **BurstPaste coalescer**: terminals/tmux configs without ?2004 deliver a paste as a burst of printable keys; the reader now coalesces a fast burst with a matching bracket into one UiInput::Paste, so the editor still sees one paste event (same collapse, one undo unit).
- **Kitty keyboard protocol probe + modifyOtherKeys stance**: startup probes kitty CSI-u and arms the TS stance; every surface start also RESETS modifyOtherKeys mode 2, because crossterm 0.28 has no case for CSI 27;mods;key~ and drops the whole input buffer on the parse error (a sticky mode 2, armed by any other pane, loses every shift-modified printable). Divergence from TS (which arms the mode-2 fallback) documented in docs/FEATURE_PARITY.md.
- **Shifted-printable decode fix**: a trailing separator in a key id (shift+=) previously split into empty segments and decoded to nothing (the editor dropped +); now decodes to the literal plus. Any literal + key id is covered.
- **Alt-key labels**: platform-aware TS formatKeyPart labels (darwin "Option+" prefix instead of "alt+").
- **Editor undo**: unit test that one undo step removes a whole paste (handlePaste pushes one undo snapshot) — no paste-internals change.
- **Telemetry**: `tui enhanced keys` event (kitty/modifyOtherKeys booleans, primitives only), emitted at settle; row added to docs/telemetry-events.md.
